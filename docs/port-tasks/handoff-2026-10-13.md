## How the user and Claude run captures

- The user says when they are in position. Claude finds the game's process ID with `tasklist`, starts the capture as a background task with a plan file of short F9 labels, and stops it when the user says done. Stopping by killing the process is safe: the trace flushes about every second.
- No screenshots (they are opt-in), and no walking long lists. Labels can be messy: rely on the continuous trace and the game's own input record (CVS1: actor+0x5BA, down bit 0x1000) for timing.
- One labelled sample per state is not evidence. CVS1 produced two coincidences that way; repeat a state at least three times.

## Tooling gotchas found today

- **Shell escapes.** Python or C sent through a Bash heredoc can have `\n` or `\x..` turned into real control characters. That corrupted a committed test file once (fixed in `4846bc2`). Write such scripts with the Write tool, or use `bytes.fromhex`.
- **The mod's own hooks.** The mod hooks code that capture tools verify. `collection_state_capture.OWN_HOOKS` lists the hook sites, and a new frame hook must be added there or the tool will refuse to start.
- **Line endings.** Sources are CRLF in the working copy, with autocrlf on. Edit scripts preserve line endings.
- **Validation:** all 40 `tools/run_*.ps1` with each exit code checked, the Python suites, `python tools\sabotage_match_audio.py`, `python tools\sabotage_transition.py`, the `--check` flags of the three fixture and name generators, `.\build.ps1`, and `git diff --check`.
- **Deploy:** confirm the game is closed (`tasklist`), copy the installed DLL to a dated `.bak` and verify its hash, run `.\build.ps1 -Deploy`, and record the hash in the relevant listening doc.
